الإدارة والربط التقني

للفريق التقني فقط — إعداد مصادر البيانات والتحقق من صحتها.

أول موصّل تم تجهيزه: تقييمات Google عبر Places API (New) — قيد الإعداد بانتظار تفعيل Cloud Billing ومفتاح API ومعرّفات الفروع.

التمييز التقني بين تحديث البيانات المحلية والجمع من المنصات:

  • إعادة تحميل البيانات المحلية (Local Cache Reload): يقتصر على قراءة ملفات dist/data/records.json داخل المتصفح، ولا يُجري أي استعلام شبكي مع Google أو YouTube أو Meta.
  • جدولة الجمع من المنصات (Platform Ingestion Schedule): يتطلب تشغيل نصوص الجمع في بيئة الخادم/الخلفية (backend/collect-*.mjs) عبر مهام مجدولة لجلب أحدث التقييمات والتفاعلات من واجهات المنصات وتحديث ملف السجلات.

تسجيل شركة لا يفعّل مجمّعها. يجب توثيق الحسابات والفروع والصلاحيات لكل شركة. لا توجد محاكاة تحول بيانات مختلقة إلى سجلات حقيقية.

  1. أدخل معرّفات الأماكن الموثقة للفروع في backend/branches.json.
  2. شغّل: GOOGLE_PLACES_API_KEY=… node backend/collect-google-places.mjs
  3. يكتب المجمّع dist/data/records.json (لكل تقييم: رابطه المباشر وتاريخ نشره وتاريخ جمعه) وdist/data/runs.json.
  4. تعرض اللوحة السجلات الموثقة تلقائياً وتحسب الأرقام منها فقط.
  5. تصنيف المشاعر والموضوع يتم بمراجعة بشرية (حقل reviewed_by)؛ لا يوجد نموذج آلي معتمد بعد، ولا تُعرض أي نسبة دقة غير مثبتة.

قيود معروفة: يعيد Places API خمسة تقييمات كحد أقصى لكل فرع في كل طلب، لذلك لا يمثل كامل التقييمات. يجب الالتزام بشروط Google في عرض الإسناد ومدة الاحتفاظ بالمحتوى. ربط Google Analytics 4 ومنصات التواصل لم يُنفذ بعد.
